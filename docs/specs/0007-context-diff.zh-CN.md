# Spec 0007: 两个请求之间的上下文差异

## Status

Draft

配对 Plan：[`docs/plans/0007-context-diff.md`](../plans/0007-context-diff.md)

## Problem And Scope

"模型所见" 回答一个请求的上下文里有什么：`reconstruct` 返回的槽位（系统提示词、工具、摘要、消息、本轮），每个槽位为 `present`、`empty` 或 `unavailable`，压缩移除的事件，以及 agent 记录的 token 数。有两个问题需要不止一个请求（[#102](https://github.com/PerfectPan/agent-trace/issues/102)）：

1. 两个请求之间有什么变化：哪些事件进入上下文，哪些离开，哪些被压缩隐藏，系统提示词或工具列表是否变化。常见情形是压缩前后的两个请求，以及相邻的两个请求。
2. 整个会话中 token 按槽位花在了哪里。

本 Spec 在工作区检查器中加入同一通道上两个请求的上下文差异，在开发服务器和报告中都可用。第二个问题只回答到日志允许的程度；见 [Composition over time](#composition-over-time)。

不包括：MCP 工具、费用、`@rivus/agent-kit` 的任何改动、导出（ATIF、OTLP、报告内容）、两个会话之间的差异、消息文本的差异。

## Behavioral Requirements

- 检查器在"模型所见"和"原始记录"之间有一个"对比"标签页。选中的事件是请求时，该标签页把它与同一通道的另一个请求对比。
- 对比对象按以下优先顺序确定：用户选择的请求，只要它仍是选中请求所在通道上除选中请求外的请求；否则为该通道上的上一个请求；通道的第一个请求则取下一个请求。
- 用户有三种方式选择对比对象：列出该通道其他所有请求的选择框（带记录的输入 token，或"未记录"）；"上一个请求"快捷选项；在时间线主通道的请求柱条上按住 Shift 点击。当选中请求所在通道上有压缩发生在它之前时，出现"最近一次压缩之前"快捷选项；它选择该压缩之前该通道的最后一个请求。
- 请求的"模型所见"链接到"对比"标签页。
- 无论两者中哪一个被选中，差异总是从较早的请求指向较晚的请求；选中的请求有标记。
- 差异显示：
  - 两个请求记录的输入 token 及其差值，仅当两者都有记录时显示；否则用一行说明不显示差值；
  - 两个请求之间该通道上的每次压缩，带记录的压缩前 → 压缩后 token 数，或"未记录"；
  - 每个槽位：系统提示词显示"相同"或"已变化"；工具显示"相同"、增加和移除的工具名称，或在某个定义没有名称时显示"已变化 · 未记录工具名称"；摘要、消息和本轮显示增加、移除和保留的事件数，以及槽位状态的变化（例如 空 → 有内容）；
  - 进入上下文的事件（之后在某个槽位中、之前不在任何槽位中），每个都可选中；
  - 两个请求之间被压缩隐藏的事件，与"模型所见"一样加删除线，每个都可选中。
- 任一请求的日志未记录的槽位画成斜线填充并标为"unavailable"，不列出它的变化。
- 标签页说明槽位数量是事件数，不是 token 数。
- "对比"标签页打开时，时间线用虚线框画出对比对象，与选中请求的实线框并列。
- 事件类型仍是标记；差异中的文本都不使用错误色。

## Domain Invariants

- 差异由同一个 trace（浏览器中是视图 trace）上的两次 `reconstruct` 结果计算；它继承 `reconstruct` 的所有规则：按通道的前缀、`shadowedBy`、prompt 快照，以及日志未记录的内容为 `unavailable`。
- 差异列为被压缩隐藏的事件，正好是这样的事件：其 `shadowedBy` 指向的压缩在较晚请求的前缀中，而不在较早请求的前缀中。
- token 数只用记录的数字：每个请求的 `request.inputTokens`，以及每次压缩的 `preTokens` / `postTokens`。不给任何槽位分配 token 数，也不用缺失的数字计算差值。
- 系统提示词和工具列表按内容比较。视图 trace 把重复的值替换为指向持有该值的快照的引用；比较时沿引用找到该值，视图截短过的两个值不会因截短后的文本相同而被判为相等。
- 每个通道是独立的模型对话。不同通道上的两个事件不做比较；kernel 以这个原因拒绝这一对事件。

## Composition Over Time

agent 对每个请求记录一个输入 token 总数，在压缩时记录压缩前后的 token 数。它们不记录这些 token 如何分布在系统提示词、工具、摘要和消息之间。按槽位的 token 构成随时间的变化只能从文本长度估算，本产品不做估算。

能如实展示的内容已经展示：记录的总数随时间的变化就是时间线的柱高，每次压缩的压缩前 → 压缩后是它的标签。每个槽位的事件数不能衡量 token（一个工具结果可能比一百条消息还大），把它随时间画成图放在 token 柱条旁边，会被读成 token 的划分。因此差异只在用户选定的两个请求之间显示每个槽位的事件数，标明是事件数，并与记录的总数并列。本 Spec 不包括随时间变化的构成视图。

## Acceptance Examples

### CD-S1: 跨压缩对比

Given 一个 Claude Code 会话，有三个请求、一次自动压缩（压缩前 3.5k，压缩后 400），之后还有两个请求，
When 用户选中压缩后的第一个请求并打开"对比"，
Then 对比对象是压缩前的最后一个请求，差异显示 "3k → 600" 和 "−2.4k input tokens"、一行压缩 "3.5k → 400"、进入的事件中包含压缩摘要，被压缩隐藏的事件数与"模型所见"列出的被移除事件数相同。

### CD-S2: 最近一次压缩之前

Given 同一个会话，
When 用户选中最后一个请求并打开"对比"，
Then 对比对象是上一个请求（600 → 900），没有压缩，也没有被隐藏的事件；点击"最近一次压缩之前"后，对比对象是 3k 的请求，并出现一行压缩。

### CD-S3: 从时间线选择

Given 在某个请求上打开了"对比"，
When 用户按住 Shift 点击主通道上另一个请求的柱条，
Then 该请求成为对比对象，时间线用虚线框画出它，选中项不移动。

### CD-S4: 缺失的数据保持缺失

Given 一个日志不记录系统提示词和工具列表的会话，
When 对比两个请求，
Then 系统提示词和工具两行为斜线填充、"unavailable"，不列出变化；任一请求没有记录输入 token 时，不显示差值。

### CD-S5: Prompt 快照

Given 一个有 prompt 快照的会话，
When 对比两个处于同一份记录的系统提示词之下的请求，
Then 系统提示词为"相同"，在完整 trace 和视图 trace 上都一样；工具列表变化时，列出增加和移除的工具名称；某个工具定义没有名称时，工具一行说明未记录名称；工具列表在较早请求之后才首次记录时，工具一行为"unavailable"。

### CD-S6: 同一个请求

Given 任一请求，
When kernel 将它与自身做差异，
Then 没有事件进入、离开或被隐藏，每个槽位都没有增加或移除的事件，有记录时输入 token 差值为 0。

### CD-S7: 报告模式与中文

Given 用 `estela build` 从一个有压缩的会话生成、从 `file://` 打开的报告，
When 用户在压缩后的某个请求上打开"对比"并切换到中文，
Then 差异与开发服务器上相同，所有标签都是中文。

### CD-S8: 通道

Given 一个有子代理的会话，
When 对比子代理通道上的两个请求，
Then 差异只涉及该通道的事件；选择框从不提供其他通道的请求，kernel 以原因 `different-lanes` 拒绝位于不同通道的一对事件。

### CD-S9: 无可对比内容

Given 选中的事件不是请求，或它所在通道没有其他请求，
When 用户打开"对比"，
Then 标签页用一行说明这一点，不显示差异。

## Compatibility And Constraints

- 在开发服务器和报告中行为相同：差异在浏览器中基于视图 trace 计算，不新增 RPC。
- 不改动 CLI 命令、canonical trace 格式、RPC 接口定义或报告内容。
- 界面文字提供英文和简体中文。
