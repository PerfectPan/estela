# Spec 0008：按会话、轮次和请求显示费用

## 状态

Draft

配对 Plan：[`docs/plans/0008-cost.md`](../plans/0008-cost.md)

## 问题与范围

查看器显示 Token 数，但不显示费用（issue #101）。阅读会话的人无法判断是哪个轮次、子代理或请求让会话变贵，也看不出输入中有多少来自提示缓存。`@rivus/agent-kit` 已经提供计价（`/cost`）和 LiteLLM 价格快照（`/cost/prices`），查看器尚未使用。

范围内：

- 按 CLI 自带的价格快照，计算每个请求已记录 Token 的目录价，按请求、轮次、子代理泳道和会话显示，并在代理记录了相应 Token 类别时给出输入、缓存读取、缓存写入和输出的分项以及缓存命中率。
- 开发服务器工作区和静态报告显示相同的数字。
- 凡显示费用之处，都能找到价格快照版本。
- 只在目标格式定义了费用字段时，才在导出中写入费用。

不在范围内：预算和告警、用户自定义价格、对缺失用量或未知模型价格的任何估算、代理自己记录的金额、Codex 优先服务等级的倍率、会话浏览器中的费用（后三项未交付的原因见“兼容性与约束”）。

## 行为要求

- R1. 请求的每个模型分项都记录了输入和输出 Token、注明了模型，且快照中有该模型的价格时，请求才计价。其费用是 kit 的 `priceRecord` 金额：每类 Token 按该模型价格计费，长上下文档位按 kit 的方式逐请求生效。
- R2. 无法计价的请求显示费用不可用并给出原因：未记录用量、未记录输入或输出 Token、未记录模型，或没有所列模型的价格。它从不显示为 $0，也从不估算。记录了 0 输入和 0 输出 Token 的请求费用为 $0。
- R3. 合计（轮次、泳道、会话）累加已计价的请求。有请求未计价时，用数量说明（例如“4 个请求中有 1 个未计价”，空间不足时写成“$0.07 · 1 个未计价”）。全部未计价时，显示不可用，并给出各原因及其数量。
- R4. 会话页头显示会话的目录价费用。合计完整时标签带缓存命中率，否则带部分或不可用的说明；悬停提示注明快照（`LiteLLM <date> · <commit>`），说明该数字不是实际账单，并列出分项和命中率。
- R5. 每个轮次标题在请求数和时长之后显示该轮次的费用；子代理的请求计入派生它的轮次。
- R6. 在“代理”布局中，每个泳道标题显示该泳道的费用；主泳道只含它自己的请求。
- R7. 选中请求行时，检查器的元信息行显示其费用，下方显示该请求所记录 Token 类别的分项、缓存命中率和快照版本；未计价的请求在该处显示原因。
- R8. 两种界面语言中金额都按美元格式化并使用 `$` 符号：一美分及以上保留两位小数，一美分以下保留两位有效数字，再小则显示 `<$0.0001`。文案来自英文和简体中文字典。
- R9. 从 `file://` 打开的报告显示与同一会话工作区相同的数字，无需服务器。
- R10. `export-atif` 为请求已计价的每个 step 写入 `metrics.cost_usd`；只有当该 trajectory 所在泳道的所有请求都已计价时才写入 `final_metrics.total_cost_usd`（根 trajectory：会话的所有请求，包括子代理；被上下文压缩隐藏的请求虽不生成 step，也计入）；并在根的 `extra.estela.pricing` 中注明快照和未计价数量。`export-otlp` 不变，因为所固定的 GenAI 语义约定没有定义费用属性。

## 领域不变量

- 缺失数据就是不可用：只有已记录的 Token 在有列出价格时才有费用；部分合计总会说明自己是部分的。
- 该数字是目录价，不是账单，凡界面解释它的地方都这样说明。
- 显示或导出的每个费用都注明生成它的快照版本。
- 计价是基于 trace 的纯计算；不存储任何费用数据。

## 验收示例

### C1：带缓存类别的已计价请求

- 假设一个 `claude-sonnet-4-5-20250929` 请求记录了 26,200 个输入 Token（其中 20,000 个缓存读取、5,000 个缓存写入）和 800 个输出 Token，
- 当选中它时，
- 则检查器显示 $0.04，以及输入 $0.0036、缓存读取 $0.006、缓存写入 $0.02、输出 $0.01、缓存命中 76% 和快照版本。

### C2：未计价的模型

- 假设一个 `claude-test` 请求，快照中没有这个模型，
- 当选中它并绘制其轮次标题时，
- 则检查器显示“费用不可用：没有 claude-test 的价格”，轮次标题显示“费用不可用”。

### C3：缺失用量

- 假设一个请求没有记录任何 Token 数，或只记录了输出 Token，
- 则它以“未记录用量”或“未记录输入或输出 Token”为由未计价，包含它的任何合计都把它计为未计价。

### C4：部分合计

- 假设一个会话有四个请求，其中一个未计价，
- 则页头显示其余三个的合计以及“4 个请求中有 1 个未计价”。

### C5：子代理泳道

- 假设一个子代理泳道有一个已计价的请求，
- 则“代理”布局的泳道标题显示该请求的费用，派生该子代理的轮次也计入它。

### C6：报告

- 假设用 `estela build` 构建 C4 的会话，
- 当从 `file://` 打开报告时，
- 则页头显示相同的合计和相同的部分说明。

### C7：ATIF 导出

- 假设一个 trace 的请求全部已计价，并有一个子代理，
- 当用 `export-atif` 导出时，
- 则每个 agent step 带 `metrics.cost_usd`，每个 trajectory 的 `final_metrics.total_cost_usd` 是其合计（根的合计包含子代理），`extra.estela.pricing` 注明快照；若有一个请求未计价，则不写合计，`unpricedRequests` 计入它。

## 兼容性与约束

- 公开接口：没有新命令或参数。ATIF 导出新增可选的 ATIF 字段；OTLP 导出不变。
- 持久化数据：无。会话索引不变，因此不需要索引修订。
- 以下内容未交付，因为 `@rivus/agent-kit` 0.24.1 不提供所需数据，且本次改动不修改 kit：
  - 会话浏览器行和预览中的费用：索引摘要来自 kit 的有界摘要遍历，它不按请求记录模型或缓存类别；为一行计价意味着加载整个 transcript。
  - 代理自己记录的金额（opencode、Pi、Grok、ZCode）和 Codex 优先服务等级的倍率：kit 的用量解码器会报告它们，但查看器读取的 transcript `request` 事件不携带它们。
- 运行边界：每个已加载的 trace 在浏览器中计价一次；web bundle 增加 kit 的计价代码和快照（gzip 后约 8 KB）。
