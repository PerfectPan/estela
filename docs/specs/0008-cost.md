# Spec 0008: Cost per session, turn, and request

## Status

Draft

Paired Plan: [`docs/plans/0008-cost.md`](../plans/0008-cost.md)

## Problem And Scope

The viewer shows token counts but no cost (issue #101). Someone reading a
session cannot tell which turn, subagent, or request made it expensive, or how
much of the input came from the prompt cache. `@rivus/agent-kit` already ships
pricing (`/cost`) and a LiteLLM price snapshot (`/cost/prices`) that the viewer
does not use.

In scope:

- The list price of the tokens each request recorded, at the price snapshot
  bundled with the CLI, shown per request, per turn, per subagent lane, and per
  session, with the input, cache-read, cache-write, and output shares and a
  cache hit rate where the agent records those token classes.
- The same numbers in the dev server workspace and in a static report.
- The price snapshot version, discoverable wherever a cost is shown.
- Cost in exports only where the target format defines a field for it.

Excluded: budgets and alerts, user-defined prices, any estimate of missing
usage or of an unknown model's price, amounts an agent logs itself, Codex's
priority-tier multiplier, and cost in the session browser (see Compatibility
And Constraints for why the last three are not delivered).

## Behavioral Requirements

- R1. A request is priced when every model share of it records input and output
  tokens, names a model, and the snapshot has a price for that model. Its cost
  is the kit's `priceRecord` amount: each token class at the model's price, the
  long-context tier applied per request as the kit applies it.
- R2. A request that cannot be priced shows cost as unavailable with the
  reason: no usage recorded, input or output tokens not recorded, no model
  recorded, or no price for the named models. It is never shown as $0 and never
  estimated. A request that records 0 input and 0 output tokens costs $0.
- R3. A sum (turn, lane, session) adds the priced requests. When some requests
  are unpriced, it says so with the count (for example "1 of 4 requests
  unpriced", or "$0.07 · 1 unpriced" where space is short). When none is
  priced, it shows unavailable with the reasons and their counts.
- R4. The session header shows the session's list cost. Its label carries the
  cache hit rate when the sum is complete, or the partial or unavailable note;
  its tooltip names the snapshot (`LiteLLM <date> · <commit>`), says the
  number is not the amount billed, and lists the shares and hit rate.
- R5. Each turn header shows the turn's cost after its request count and
  duration; subagent requests count in the turn that spawned them.
- R6. In the Agents layout, each lane header shows that lane's cost; the main
  lane holds only its own requests.
- R7. Selecting a request row shows its cost in the inspector's meta line and,
  under it, the shares of the token classes the request records, its cache hit
  rate, and the snapshot version; an unpriced request shows the reason there.
- R8. Amounts are formatted as USD with the `$` symbol in both UI languages:
  two decimals from a cent up, two significant digits below a cent, and
  `<$0.0001` below that. Strings come from the English and Simplified Chinese
  dictionaries.
- R9. A report opened from `file://` shows the same numbers as the workspace of
  the same session, without a server.
- R10. `export-atif` writes `metrics.cost_usd` for each step whose request is
  priced, `final_metrics.total_cost_usd` only when every exported request of
  that trajectory (subagents included for the root) is priced, and names the
  snapshot and the unpriced count in the root's `extra.estela.pricing`.
  `export-otlp` is unchanged, because the pinned GenAI semantic conventions
  define no cost attribute.

## Domain Invariants

- Missing data is unavailable: a cost exists only for recorded tokens at a
  listed price; a partial sum always says it is partial.
- The number is a list price, not a bill, and the UI says so wherever it is
  explained.
- Every cost shown or exported names the snapshot version that produced it.
- Pricing is pure computation over the trace; nothing about cost is stored.

## Acceptance Examples

### C1: Priced request with cache classes

- Given a request of `claude-sonnet-4-5-20250929` recording 26,200 input
  tokens of which 20,000 cache reads and 5,000 cache writes, and 800 output
  tokens,
- When it is selected,
- Then the inspector shows $0.04 with input $0.0036, cache read $0.006, cache
  write $0.02, output $0.01, 76% cache hits, and the snapshot version.

### C2: Unpriced model

- Given a request of `claude-test`, a model the snapshot does not list,
- When it is selected, and its turn header is drawn,
- Then the inspector says "Cost unavailable: no price for claude-test" and the
  turn header says "cost unavailable".

### C3: Missing usage

- Given a request that records no token counts, or only output tokens,
- Then it is unpriced with "no usage recorded" or "input or output tokens not
  recorded", and any sum that holds it counts it as unpriced.

### C4: Partial sum

- Given a session with four requests, one of them unpriced,
- Then the header shows the sum of the other three and "1 of 4 requests
  unpriced".

### C5: Subagent lane

- Given a subagent lane with one priced request,
- Then the Agents layout's lane header shows that request's cost, and the turn
  that spawned the subagent includes it.

### C6: Report

- Given the session of C4 built with `estela build`,
- When the report opens from `file://`,
- Then its header shows the same sum and the same partial note.

### C7: ATIF export

- Given a trace whose requests are all priced, with a subagent,
- When exported with `export-atif`,
- Then each agent step carries `metrics.cost_usd`, each trajectory's
  `final_metrics.total_cost_usd` is its sum (the root's includes the subagent),
  and `extra.estela.pricing` names the snapshot; with one unpriced request the
  totals are absent and `unpricedRequests` counts it.

## Compatibility And Constraints

- Public API: no new command or flag. The ATIF export gains optional ATIF
  fields; the OTLP export is unchanged.
- Persisted data: none. The session index is unchanged, so no index revision.
- Not delivered, because `@rivus/agent-kit` 0.24.1 does not provide what they
  need and this change does not modify the kit:
  - Cost in the session browser rows and preview: the index summary comes from
    the kit's bounded summary pass, which records no model or cache classes per
    request; pricing a row would mean loading its whole transcript.
  - Amounts an agent logs itself (opencode, Pi, Grok, ZCode) and Codex's
    priority-tier multiplier: the kit's usage decoders report them, but its
    transcript `request` events, which the viewer reads, do not carry them.
- Operational bounds: pricing runs once per loaded trace in the browser; the
  web bundle grows by the kit's pricing code and snapshot (about 8 KB gzip).
