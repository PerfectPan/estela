## 1. 背景与目标

### 1.1 现状与约束

- 每个 `request` 事件携带 kit 的 `RequestPayload`：`model`、`usage`（`inputTokens` 含缓存读取和写入、`outputTokens`、`cacheReadTokens`、`cacheWriteTokens`、`cacheWrite1hTokens`），聚合记录另有 `granularity`、`modelCalls` 和 `usageByModel`。它不携带代理记录的金额，也不携带计价倍率。
- `@rivus/agent-kit` 0.24.1 导出 `/cost`（`createPricing`、`priceRecord`、`summarize`，12 KB，无任何导入）和 `/cost/prices`（`litellmPrices`，278 个模型，以及 `litellmPricesVersion` = `<date>+<commit>+<digest>`；55 KB，gzip 后 5 KB，无任何导入）。`priceRecord` 为一条 `UsageRecord` 计价，按模型返回分项，模型没有价格时 `cost` 缺省。
- 只有 `apps/cli` 在运行时导入 kit（`AGENTS.md`、根目录 `vite.config.ts` 的 lint 规则）。kernel 是纯函数且可在浏览器运行（`scripts/check-browser-bundle.mjs`）。
- 工作区在浏览器中从视图 trace 计算投影（轮次、泳道）；报告没有服务器，所以工作区计算的任何内容都必须能从内嵌的视图 trace 算出。
- 会话浏览器的数字来自索引，由 kit 的有界 `summarizeSession` 遍历填充；该遍历只返回总数（没有模型和缓存类别），并且有测试保证它不把 transcript 全部载入内存（`rows-memory.test.ts`）。
- 改动前的测量值：web JS 318,057 B（gzip 102,561 B）；打包的 tarball 570,197 B。

### 1.2 问题

Spec 0008：按请求、轮次、泳道和会话显示目录价费用，说明合计是部分的还是不可用的，并保持报告和导出一致。

### 1.3 目标

- 用一个纯函数为 trace 计价；所有界面读取它的结果。
- 任何地方都不估算；每个未计价请求都有原因。
- 报告在不新增传输数据的前提下显示相同的数字。

### 1.4 非目标

预算、告警、用户价格、估算、会话浏览器中的费用、代理记录的金额、Codex 优先服务等级倍率（原因见第 7 节）。

## 2. 概要

### 2.1 总体做法

kernel 新增基于 kit `priceRecord` 的 `priceTrace(trace, pricing)`，以及把 kit 快照包装为查价对象的 `snapshotPricing()`。web 应用在 `createWorkspaceState` 中对每个已加载会话调用一次，并把结果交给页头、事件列表行和检查器。`toAtif` 接收可选的 `pricing`；`export-atif` 传入快照。

### 2.2 关键决定

| ID | 决定 | 原因 |
|---|---|---|
| D1 | 在浏览器中通过 kernel 计价 | 工作区和报告本来就从视图 trace 计算投影；在那里计价不需要改 RPC 或报告格式，报告的数字天然一致。快照加计价代码使 web bundle 增加约 55 KB 原始大小、8 KB gzip（实测），相对 103 KB gzip 的 bundle 很小。 |
| D2 | kernel 可以在运行时导入 `@rivus/agent-kit/cost` 和 `/cost/prices`；其他不变 | 这两个入口不导入任何东西（kit README：“anywhere, no imports”），kernel 仍是纯函数且可在浏览器运行。web 应用只通过 kernel 使用它们，所以 `apps/web` 仍遵守只导入类型的规则。`AGENTS.md`、`CONTRIBUTING.md`、根目录 `vite.config.ts` 的 lint 模式（为 kernel 排除这两个入口）和 `check-layers.mjs` 的注释写明这一例外。 |
| D3 | 未计价原因按优先级：`no-usage`、`incomplete-usage`（缺输入或输出）、`no-model`、`no-price` | kit 把缺失的计数按 0 计费；承诺只显示已记录数字的查看器不能把这种少算的结果当作价格显示。按模型拆分的请求只有在每个分项都计价时才计价。 |
| D4 | 0 输入和 0 输出 Token 的请求无论模型都计为 $0 | 没有产生计费（Claude Code 的 `<synthetic>` 记录）；把它们标为未计价会让大多数会话无故变成“部分”。 |
| D5 | 分项通过对 `priceRecord` 的线性探测得到 | kit 每个分项只返回一个金额。固定分项的输入后，档位选择固定，费用对每个类别是线性的；三次探测（无缓存、只读缓存、只写缓存）得到各费率，分项之和等于 kit 的总额。另写一份 kit 的公式可能与它产生偏差。缓存读取加写入超过输入的计数不给分项。 |
| D6 | 缺少 `granularity` 视为一次请求 | 适配器写每次调用的请求事件时不带该字段（Claude Code）；kit 自己的用量记录把它们标为 `request`。 |
| D7 | 不向 `index.sqlite` 写入任何内容；不提升 `INDEX_CONTENT_REVISION` | 没有 kit 的支持无法为索引计价（第 7 节），而工作区每次加载都重新计价，所以新快照不需要失效处理。 |
| D8 | ATIF：每个 step 写 `cost_usd`，仅在完整时写 `total_cost_usd`，并写 `extra.estela.pricing` | ATIF v1.8 定义了 `Metrics.cost_usd` 和 `FinalMetrics.total_cost_usd`（“包括子代理的费用”）；部分合计会被当作完整合计阅读。`notes` 说明该金额是目录价。 |
| D9 | OTLP 不变 | 所固定的 semconv（`gen-ai-dev/1.42.0-dev`）和当前 `semantic-conventions-genai` 注册表都没有定义费用属性。 |
| D10 | 会话浏览器不显示费用 | 计价需要每个请求的模型和缓存类别；有界摘要遍历不返回这些信息，而加载每个 transcript 会破坏目录的内存上限。 |

## 3. 详细设计

### 3.1 Kernel

`packages/kernel/src/price-trace.ts`：

- `TracePricing { pricing: Pricing; version: string }`。
- `priceRequest(trace, event, pricing): RequestCost`，是 `PricedRequest { kind: 'priced'; usd; shares? }` 与 `UnpricedRequest { kind: 'unpriced'; reason; models }` 的联合类型，两者都带 `eventId`、`laneId` 和已记录的 `tokens`（输入、缓存读取、缓存写入）。
- `sumCosts(costs): CostTotal`，包含 `requests`、`priced`、`usd`（全部未计价时缺省）、按原因的 `unpriced` 计数、`unpricedModels`、`shares`（仅当每个已计价请求都有分项时）和 `cacheHitRate`（在同时记录两者的请求上，缓存读取除以输入）。
- `priceTrace(trace, pricing): TraceCost`，包含 `version`、按事件 id 的 `requests`、`total` 和按泳道 id 的 `lanes`；`costOfEvents(cost, eventIds)` 为一个轮次求和。

`packages/kernel/src/snapshot-pricing.ts`：`snapshotPricing()` 在首次调用时构建 `createPricing(litellmPrices)`，因此从不调用它的 rpc bundle 不包含价格表。

`toAtif(trace, { pricing? })`：step 的 metrics 增加 `cost_usd`；每个 trajectory 的请求（根 trajectory 还包括所有内嵌 trajectory 的请求）全部已计价且至少有一个时，写入 `final_metrics.total_cost_usd`；根的 `extra.estela.pricing = { version, unpricedRequests }`。

### 3.2 Web

- `workspace-state.ts`：`cost = priceTrace(trace, snapshotPricing())`，以及每个轮次分组的 `turnCosts`；两者通过 `RowContext` 传给事件列表。
- `session-header.tsx`：第八个 `Metric`（`data-testid="session-cost"`）；`Metric` 新增 `muted`、`title` 和 `testId`。
- `turn-header.tsx`、`lane-header.tsx`：在请求数之后显示费用，并带计价依据的悬停提示。
- `inspector.tsx`：元信息行显示请求费用；费用行（`data-testid="request-cost"`）显示分项、命中率和版本，或显示原因。
- `lib/cost-text.ts`：所有费用文案；`lib/format.ts`：`formatUsd`、`formatPercent`；字典：`en` 和 `zh-CN` 中的 `cost` 部分。

### 3.3 CLI

`export/write-export.ts` 把 `snapshotPricing()` 传给 `toAtif`。

### 3.4 失败与恢复

| 情况 | 行为 |
|---|---|
| 未知模型 | 请求未计价（`no-price`，附模型）；合计注明为部分 |
| 缺失或不完整的用量 | 请求未计价（`no-usage` / `incomplete-usage`） |
| 轮次或泳道中没有请求 | 该处不显示费用；页头显示破折号 |
| 缓存计数不一致 | 请求已计价但没有分项；合计的分项省略 |

### 3.5 兼容与迁移

传输、索引和命令都不变。ATIF 输出新增可选字段。

## 7. 风险、未决问题与后续

| Kit 缺口：transcript `request` 事件缺少代理记录的金额（`costUsd`，opencode、Pi、Grok、ZCode）和 `pricingMultiplier`（Codex 优先服务等级） | follow-up | 目录价与这些代理记录的金额不同；Codex 优先等级请求只显示实际计费的一半 | unconfirmed | 请 kit 在 `RequestPayload` 上携带这两项；之后传给 `priceRecord` |

| 快照在版本之间改变价格 | risk | 升级后同一会话显示不同的费用 | unconfirmed | 每个费用都显示版本 |
