This plan prices the recorded usage of a trace with the kit's `/cost` and its
LiteLLM snapshot (`/cost/prices`) and shows the result in the workspace, the
report, and the ATIF export. It follows issue #101.

## 1. Background and goals

### 1.1 Current behavior and constraints

- Each `request` event carries the kit's `RequestPayload`: `model`, `usage`
  (`inputTokens` including cache reads and writes, `outputTokens`,
  `cacheReadTokens`, `cacheWriteTokens`, `cacheWrite1hTokens`), and for
  aggregates `granularity`, `modelCalls`, and `usageByModel`. It carries no
  amount the agent logged and no pricing multiplier.
- `@rivus/agent-kit` 0.24.1 exports `/cost` (`createPricing`, `priceRecord`,
  `summarize`, 12 KB, imports nothing) and `/cost/prices` (`litellmPrices`,
  278 models, and `litellmPricesVersion` = `<date>+<commit>+<digest>`; 55 KB,
  5 KB gzip, imports nothing). `priceRecord` prices a `UsageRecord` and returns
  one part per model with `cost` absent when the model has no price.
- Only `apps/cli` imports the kit at runtime (`AGENTS.md`, the root
  `vite.config.ts` lint rule). The kernel is pure and browser-safe
  (`scripts/check-browser-bundle.mjs`).
- The workspace computes its projections (turns, lanes) in the browser from
  the view trace; a report has no server, so anything the workspace computes
  must be computable from the baked view trace.
- The session browser's numbers come from the index, filled by the kit's
  bounded `summarizeSession` pass, which returns totals only (no model, no
  cache classes) and is tested not to materialize the transcript
  (`rows-memory.test.ts`).
- Measured before this change: web JS 318,057 B (102,561 B gzip); packed
  tarball 570,197 B.

### 1.2 Problem

Spec 0008: show list cost per request, turn, lane, and session, say when a sum
is partial or unavailable, and keep the report and exports consistent.

### 1.3 Goals

- One pure function prices a trace; every surface reads its result.
- No estimate anywhere; reasons for every unpriced request.
- The report shows the same numbers with no new wire data.

### 1.4 Non-goals

Budgets, alerts, user prices, estimates, session-browser cost, agent-logged
amounts, Codex's priority multiplier (section 7 records why).

## 2. Outline

### 2.1 Overall approach

The kernel gets `priceTrace(trace, pricing)`, built on the kit's `priceRecord`,
and `snapshotPricing()`, the kit's snapshot as a lookup. The web app calls both
once per loaded session in `createWorkspaceState` and hands the result to the
header, the ledger rows, and the inspector. `toAtif` takes an optional
`pricing`; `export-atif` passes the snapshot.

### 2.2 Key decisions

| ID | Decision | Reason |
|---|---|---|
| D1 | Price in the browser, through the kernel | The workspace and the report compute projections from the view trace already; pricing there needs no RPC or report format change, and the report stays identical by construction. The snapshot plus pricing code adds about 55 KB raw, 8 KB gzip to the web bundle (measured), small next to the 103 KB gzip bundle. |
| D2 | The kernel may import `@rivus/agent-kit/cost` and `/cost/prices` at runtime; nothing else changes | Both entries import nothing (kit README: "anywhere, no imports"), so the kernel stays pure and browser-safe. The web app reaches them only through the kernel, so `apps/web` keeps the type-only rule. `AGENTS.md`, `CONTRIBUTING.md`, the root `vite.config.ts` lint patterns (negated entries for the kernel), and the `check-layers.mjs` comment state the exception. |
| D3 | Unpriced reasons, in precedence: `no-usage`, `incomplete-usage` (input or output missing), `no-model`, `no-price` | The kit charges a missing count as 0; a viewer that promises recorded numbers must not show such an undercount as a price. A request with a split by model is priced only when every share is. |
| D4 | 0 input and 0 output tokens cost $0 regardless of model | Nothing was billed (Claude Code's `<synthetic>` entries); marking them unpriced would make most sessions "partial" for no reason. |
| D5 | Shares from linear probes of `priceRecord` | The kit returns one amount per part. With the part's input fixed, the tier choice is fixed and the cost is linear in each class; three probes (no cache, reads only, writes only) give the rates, and the shares sum to the kit's total. A second copy of the kit's formula could drift from it. Counts with reads plus writes above input get no shares. |
| D6 | Missing `granularity` counts as one request | Adapters write per-call request events without it (Claude Code); the kit's own usage records call them `request`. |
| D7 | Nothing enters `index.sqlite`; no `INDEX_CONTENT_REVISION` bump | The index cannot be priced without the kit (section 7), and workspace pricing is recomputed on every load, so a new snapshot needs no invalidation. |
| D8 | ATIF: `cost_usd` per step, `total_cost_usd` only when complete, `extra.estela.pricing` | ATIF v1.8 defines `Metrics.cost_usd` and `FinalMetrics.total_cost_usd` ("including cost for subagents"); a partial total would read as complete. `notes` says the amount is a list price. |
| D9 | OTLP unchanged | The pinned semconv (`gen-ai-dev/1.42.0-dev`) and the current `semantic-conventions-genai` registry define no cost attribute. |
| D10 | Session browser shows no cost | Pricing needs per-request model and cache classes; the bounded summary pass does not return them, and loading every transcript would break the catalog's memory bound. |

## 3. Detailed design

### 3.1 Kernel

`packages/kernel/src/price-trace.ts`:

- `TracePricing { pricing: Pricing; version: string }`.
- `priceRequest(trace, event, pricing): RequestCost`, a union of
  `PricedRequest { kind: 'priced'; usd; shares? }` and
  `UnpricedRequest { kind: 'unpriced'; reason; models }`, both with `eventId`,
  `laneId`, and the recorded `tokens` (input, cache read, cache write).
- `sumCosts(costs): CostTotal` with `requests`, `priced`, `usd` (absent when
  nothing is priced), `unpriced` counts per reason, `unpricedModels`, `shares`
  (only when every priced request has them), and `cacheHitRate` (cache reads
  over input across requests that record both).
- `priceTrace(trace, pricing): TraceCost` with `version`, `requests` by event
  id, `total`, and `lanes` by lane id; `costOfEvents(cost, eventIds)` sums a
  turn.

`packages/kernel/src/snapshot-pricing.ts`: `snapshotPricing()` builds
`createPricing(litellmPrices)` on first call, so the rpc bundle, which never
calls it, drops the table.

`toAtif(trace, { pricing? })`: step metrics get `cost_usd`; each trajectory's
`final_metrics.total_cost_usd` is its lane's `CostTotal` from `priceTrace`
(the root: the trace total, subagents included), set only when every request
is priced. The totals come from the lanes, not the steps, so a request a
compaction hid (which produces no step) still counts; the root's
`extra.estela.pricing = { version, unpricedRequests }`.

### 3.2 Web

- `workspace-state.ts`: `cost = priceTrace(trace, snapshotPricing())` and
  `turnCosts` per turn group; both reach the ledger through `RowContext`.
- `session-header.tsx`: an eighth `Metric` (`data-testid="session-cost"`);
  `Metric` gains `muted`, `title`, and `testId`.
- `turn-header.tsx`, `lane-header.tsx`: the cost after the request count, with
  the basis tooltip.
- `inspector.tsx`: the request's cost in the meta line; a cost line
  (`data-testid="request-cost"`) with shares, hit rate, and version, or the
  reason.
- `lib/cost-text.ts`: all cost wording; `lib/format.ts`: `formatUsd`,
  `formatPercent`; dictionaries: a `cost` section in `en` and `zh-CN`.

### 3.3 CLI

`export/write-export.ts` passes `snapshotPricing()` to `toAtif`.

### 3.4 Failures and recovery

| Condition | Behavior |
|---|---|
| Unknown model | Request unpriced (`no-price`, with the model); sums say partial |
| Missing or partial usage | Request unpriced (`no-usage` / `incomplete-usage`) |
| No requests in a turn or lane | No cost shown there; the header shows the dash |
| Inconsistent cache counts | Request priced, no shares; the sum's shares are omitted |

### 3.5 Compatibility and migration

No wire, index, or command change. ATIF output gains optional fields.

## 4. Rollout and stability

Ships with the next version; rollback is reverting the change. A new kit
release with a new snapshot changes prices on the next load; the version shown
names the table.

## 6. Execution plan

### 6.1 Preconditions

`@rivus/agent-kit` 0.24.1 with `/cost` and `/cost/prices`; ATIF v1.8 field
names re-checked against Harbor's models.

### 6.2 Completion contract

Spec C1–C7 have tests; the layer rule change is written in `AGENTS.md`,
`CONTRIBUTING.md`, lint, and `check-layers.mjs`; README, overview, and design
README updated; changeset added; all gates green.

### 6.3 Execution order

1. Kernel: `price-trace.ts`, `snapshot-pricing.ts`, exports, tests; move the
   kit to the kernel's `dependencies`; lint rule.
2. ATIF cost fields and tests; CLI wiring.
3. Web: format, dictionaries, cost text, state, header, ledger, inspector.
4. E2E trace and scenarios; screenshots.
5. Docs, changeset, gates.

### 6.4 Rollback per batch

Revert the change; nothing is persisted.

## 7. Risks, open questions, and follow-up

| Item | Type | Impact | Owner | Next step |
|---|---|---|---|---|
| Kit gap: transcript `request` events lack the agent-logged amount (`costUsd`, opencode, Pi, Grok, ZCode) and `pricingMultiplier` (Codex priority tier) | follow-up | List price differs from what those agents logged; a Codex priority request shows half its billed price | unconfirmed | Ask the kit to carry both on `RequestPayload`; then pass them into `priceRecord` |
| Kit gap: the bounded summary pass returns no priceable usage | follow-up | No cost in the session browser | unconfirmed | Ask the kit for a summary that carries per-model usage by class (or a priced total with an injected `Pricing`); then store it with the snapshot version and bump `INDEX_CONTENT_REVISION` |
| Snapshot changes prices between versions | risk | The same session shows a different cost after an upgrade | unconfirmed | The version is shown with every cost |
| Share probes rely on the kit's formula being linear per class | risk | Shares omitted if a future formula is not | unconfirmed | The sum check drops shares that do not add up |
