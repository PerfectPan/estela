# 概念

Estela 只展示代理日志所记录的内容，不附加任何其他内容。以下是会话浏览器、工作区、报告和 MCP 工具中使用的术语。

## 会话

与代理进行的一次对话，按代理自身保存的形式读取：JSONL 文件、文件目录，或数据库中的行（OpenCode）。Estela 只读取会话而不写入任何内容。会话包含标题（代理自身的标题或首条提示词）、工作目录，以及在日志有记录时的代理版本。

## 事件

日志按顺序记录的一条内容。每个事件都可以显示其来源的日志记录（「原始记录」标签页）。事件类型包括：

| 类型 | 显示为 | 含义 |
|---|---|---|
| `user` | 用户 | 你输入的提示词，或代理及工具作为用户消息注入的文本 |
| `assistant` | 回复 | 模型生成的文本 |
| `reasoning` | 推理 | 日志记录的模型推理文本 |
| `tool_call`、`tool_result` | 工具 | 模型调用的工具以及返回结果；失败的结果会带有标记 |
| `request` | 请求 | 一次模型请求及其记录的用量（见下文） |
| `system` | 系统 | 代理内部记录：提示词快照、轮次时长、指令 |
| `hook` | 钩子 | 代理运行的钩子 |
| `compaction` | 上下文压缩 | 一次上下文压缩（见下文） |
| `unknown` | 未知 | 读取器保留但未解析的记录 |

不是有效 JSON 的日志行会被跳过并计入统计；这不会阻止会话加载。

## 请求

对模型的一次调用，包含日志为其记录的信息：模型、输入 Token（包含缓存读取和写入）、输出 Token、缓存读取与缓存写入 Token、结束原因以及时长。日志未记录的字段为缺失状态，而不是零。大多数代理为每次模型调用记录一条请求；Grok 按轮次记录一次用量，因此每个 Grok 请求覆盖整轮（见[支持的代理](supported-agents.zh-CN.md#已知限制)）。

## 轮次

从你在主代理输入一条提示词开始，直到下一条提示词之间的全部内容。轮次内的钩子运行会在事件列表中折叠为一行。子代理的工作归属于启动它的轮次。

## 泳道

主代理是一条泳道，它启动的每个子代理各自是一条泳道。每条泳道都是与模型之间独立的对话：一条泳道上的模型所见内容不包含另一条泳道的事件。时间线为每条泳道绘制一行，事件列表的「代理」布局也按泳道对事件分组。

## 上下文压缩

当上下文变长时，部分代理会用摘要替换较早的上下文。Estela 将上下文压缩显示为独立事件；当代理记录了压缩前后的 Token 数时一并显示（`45.5k → 15k`），并标记被移出模型视野的事件。这些事件仍保留在事件列表中（开启开关后淡化显示），也会出现在「模型所见」的「被上下文压缩移除」列表里；压缩之后模型不再看到它们。

## 模型所见

对于任意事件，Estela 仅根据日志重建该事件所在泳道当时呈现给模型的上下文。上下文拆分为以下槽位：

| 槽位 | 内容 |
|---|---|
| 系统提示词 | 当日志有记录时，显示系统提示词 |
| 工具 | 当日志有记录时，显示工具定义 |
| 摘要 | 替换较早事件的压缩摘要 |
| 消息 | 仍在上下文中的较早轮次 |
| 本轮 | 当前轮次至今的事件 |

每个槽位的状态为 `present`、`empty` 或 `unavailable`。当代理在会话期间将系统提示词和工具记录为快照时（Claude Code 2.1.268 及更高版本），各槽位使用该事件或之前最新的快照，并标明记录它的事件（`recorded at #7`）。「模型所见」还会列出已记录的 Token 数及其各自覆盖的槽位（请求的输入 Token 覆盖全部槽位），以及被上下文压缩移除的事件。结果状态为「完整」，或为「部分」并标明不可用槽位的数量。

## `unavailable`：不做估算

当日志未记录某项内容时，Estela 显示 `unavailable`（或「—」、「未记录」），而不是给出数字或猜测。它从不根据文本长度估算 Token 数，从不把请求的 Token 分摊到各个槽位，也从不为缺少 Token 或模型的请求计算价格。空白计数代表日志的限制，而不是零。

## 能力

每个代理的读取器都会声明其日志能够保存的数据类型：请求、用量、时长、推理、上下文压缩、上下文压缩 Token 数、子代理、系统提示词、工具定义、钩子。代理无法记录的计数在会话页头显示为「—」，在 MCP 工具中列为 `unavailable`。声明的能力表示代理可以记录该类数据，并不意味着每个会话都必然包含。各代理的对应表格见[支持的代理](supported-agents.zh-CN.md#各代理记录的内容)。

## Trace 与 trace id

Estela 会把会话转换为一个 trace：按顺序排列的事件加上会话详情。trace id 是代理与路径（对于 `path#sessionId` 会话，还包括会话 id）的不透明哈希。URL 和 MCP 工具只使用 trace id，从不使用文件路径。
