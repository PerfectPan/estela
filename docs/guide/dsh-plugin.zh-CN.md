# DeepSeek Harness 插件

`@rivus/dsh-estela` 将 Estela 工作区直接嵌入 DeepSeek Harness（`dsh web`），作为 Chat 和 Trajectory 旁的一个视图标签页，让你无需离开 `dsh` 或另启 CLI 服务器即可检查当前会话。

## 安装

将插件安装到 `web` profile 并启动 `dsh web`：

```sh
dsh plugin --profile web add @rivus/dsh-estela
```

插件自身没有任何配置项。它在 `dsh` 自己的进程中运行，不启动额外进程、不监听额外端口、也不自行注册 HTTP 路由。它直接从磁盘读取会话日志，并通过 `dsh` 现有的连接仅向 `dsh` 认可的 owner 提供会话内容。

仅支持 `web` profile；不支持 dsh Desktop 和 TUI profile。

## 视图显示的内容

在 `dsh web` 的对话中切换到 **Estela** 标签页时，视图会显示该会话的工作区——与 `estela` 命令行对同一日志文件展示的内容一致：

- 时间线上方一行会话数据：时长、轮次、请求、Token 数和目录价费用；会话中有上下文压缩、子代理或失败的工具调用时，也会显示这几项的数量。`dsh` 已经显示了会话标题，视图不再重复。
- 「跳转」按钮（`⌘K` / `Ctrl+K`），用来查找事件、工具或文件。
- 展示请求、泳道和上下文压缩的时间线。
- 事件列表（可按轮次或按代理分组）。
- 检查器，包含「输入」、「输出」、「模型所见」（重建出的模型收到的上下文）、「对比」（同一泳道上两个请求的上下文差异，包括被上下文压缩隐藏的事件）以及「原始记录」。

缺失的数据从不估算或编造。

视图会自动跟随 `dsh` 的外观设置（浅色、深色或跟随系统），字体、背景、文字和边框颜色也取自 `dsh`，看起来是 `dsh web` 的一部分。视图还会跟随 `dsh` 的语言设置（中文显示简体中文，其他语言显示英文），在 `dsh` 中切换时会实时更新。切换语言只翻译界面，会话文本保持原来的语言。

大型会话遵循与 CLI 相同的 12 MB 视图预算：过长文本会截短以适应预算，选中事件后会加载其完整文本。如果截短到最短文本长度后仍超过 12 MB，视图仍会照常打开并提示页面可能较慢，选中某个事件后依然可以加载其完整文本。

插件只关注当前打开的对话：不包含会话浏览器、「导出报告」以及 ATIF 和 OTLP 导出。如需这些功能，请使用 `@rivus/estela` CLI。

## 会话必须已经开始

在 `dsh web` 中，空白会话（尚未开始轮次）不会显示任何视图标签页，因此 **Estela** 标签页也不会出现。请先开始该会话，或在 `dsh` 的会话列表中打开一个已经开始的会话，即可看到 Estela 标签页。

如果会话已经开始但日志尚未写入磁盘，视图会提示「这个会话尚未在磁盘上写入日志。」。如果日志无法读取（文件缺失、不可读、未知格式代次或超过 512 MB 解压上限）或发生传输错误，错误会被限制在 Estela 视图内部并提供「重试」按钮，Chat、Trajectory 和 `dsh web` 均不受影响。

## 快照与运行中的会话

Estela 视图展示的是视图加载时磁盘上会话日志的一份快照，不会实时跟随运行中的会话。

要查看会话继续运行后写入的新轮次或新事件，请刷新 `dsh web` 页面并再次打开 Estela 标签页。

插件绝不会混用日志的两个不同状态：如果由于磁盘上的日志发生变化导致某条事件无法从当前已加载的快照中读回，视图会从磁盘重新加载当前日志，而不会把旧记录与新记录混在一起。`dsh` 进程内存中最多保留最近打开的 3 份快照。如果一个旧标签页打开了很久，期间其他标签页打开过很多快照，再在旧标签页里点击事件可能会失败，此时点击「重试」即可重新加载会话。

## 脱敏

脱敏默认开启。主目录路径和[隐私与脱敏](privacy.zh-CN.md#脱敏覆盖的范围)中列出的令牌模式会在视图和错误消息中被替换，方式与 `estela` 开发服务器一致。

如需查看未脱敏的原始会话文本，请在启动 `dsh` 的环境中设置 `ESTELA_REDACT=0`。

插件为只读，不会向磁盘写入任何内容：不修改会话日志、不写 `dsh` 文件，也不写 Estela 的会话索引。

## 卸载

从 `web` profile 中移除插件：

```sh
dsh plugin --profile web remove @rivus/dsh-estela
```

如果 `dsh web` 正在运行，Estela 标签页会在几秒内自动消失而无需重启 `dsh`，对该插件通道的调用会被拒绝；运行中的进程和端口不会有残留，且 `web` profile 目录下的依赖条目和 bundle 条目（`package.json` 及 bundle 配置）以及 `node_modules` 中的已安装目录都会被清除。如果此前用 `dsh plugin allow-version` 授予过版本豁免，该豁免单独记录在 profile 目录的 `compatibility.json` 中，删除插件不会撤销它。

## 版本范围

`@rivus/dsh-estela` 在 `engines.dsh` 中声明其支持的 DeepSeek Harness 版本范围（`>=0.2.2-rc.5 <0.3.0-0`），并要求 Node.js `>=24.9.0`。

如果你的 `dsh` 版本不在 `engines.dsh` 范围内，请见[故障排查](troubleshooting.zh-CN.md#dsh-提示插件不兼容)。
